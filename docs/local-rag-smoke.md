# Local grounded-answer smoke audit (Phase 6a)

This is an eight-question engineering smoke test, not a full answer or abstention evaluation. The questions were fixed before this run: `q01`, `q09`, `q13`, `q15`, `q25`, `q26`, `q27`, `q28`. The runtime received only each query string. Gold fields were consulted only after all eight outputs had been saved for this implementation-agent review. The unchanged question JSONL SHA-256 is `fb2dfa8a302055b9993f06933d4fa15190041ca411b582ad5263336f3192de0b`.

## Runtime and limits

- Retrieval: the existing `config/retrieval.json` selection, semantic A (`w250_o50`, top five). No document vectors were rebuilt. The pinned embedding model remained in its existing local cache.
- Generation: Qwen/Qwen3-4B-Instruct-2507 at commit `cdbee75f17c01a7cc42f958dc650907174af0554`, bfloat16 on Apple M5 Pro MPS, `model.eval()` and `torch.inference_mode()`. The model's generation config supplies EOS IDs `[151645, 151643]` and pad ID `151643`; the runtime sends an explicit attention mask.
- Greedy decoding: `do_sample=false`, at most 768 new tokens per attempt. The complete chat template is measured without truncation against a 6144-token input budget. Lowest-ranked whole chunks are removed if necessary; none were removed in this run. A second attempt is permitted only after a mechanical JSON/citation failure and uses the same passages.
- Before download, the machine had 24 GB unified memory and about 801 GiB free disk. The three generation weight shards total about 8.0 GB decimal; generation cache occupies 7.5 GiB and the embedding cache 1.1 GiB. About 790 GiB disk remained after download. A 6144+768 token run also needs KV cache and working memory; the 24 GB machine completed this run on MPS without an observed resource failure.
- Model load took 4.34 seconds after download. All eight questions shared that load. Total measured generation time was 69.47 seconds; final-attempt input lengths were 2205–2341 tokens, and all attempts together generated 1196 tokens. These timings are specific to this machine and run.

The machine-readable [smoke artifact](../eval/rag_smoke_results.json) retains all raw model outputs, submitted normalized passages, resolved citations, dropped IDs, attempts, token counts, and timings. Every displayed answered claim passed JSON and exact-substring citation checks against a passage actually sent to the model; `citations_resolved` means only that mechanical resolution succeeded. It does **not** establish entailment. The content observations above are implementation-agent review, neither independent human review nor an automated semantic-support verdict.

The smoke set is too small to estimate answer accuracy or abstention quality. It contains four answerable and four unsupported questions, with no broad coverage of alternate evidence, prompt sensitivity, or source-instruction attacks. Phase 6b will measure full answer and refusal behavior. The `q01` miss and the overlong `q09` citation remain visible for that work; this phase does not tune retrieval or add question-specific rules.
